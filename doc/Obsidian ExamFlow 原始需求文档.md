# Obsidian ExamFlow — 智能考试与自适应复习插件开发提示词

## 一、项目目标

你是一名资深 Obsidian 插件开发工程师、TypeScript 架构师和 AI 应用工程师。

请帮助我从零设计并开发一款名为 **Obsidian ExamFlow** 的 Obsidian 原生插件。

该插件主要用于各类职业资格考试、专业认证考试和知识学习，首个重点适配场景为 **软考高级系统架构设计师考试**，但系统架构必须具有通用性，不能与某一种考试强耦合。

插件需要根据用户的教材资料、考试大纲、历年真题、错题记录、重要知识点及易忘知识点，实现智能出卷、交互式考试、自动批阅、成绩分析、错题归纳和自适应复习，形成完整的学习闭环。

## 二、核心架构约束（必须遵守）

### 1. 客户端优先

- 所有能够在 Obsidian 插件内完成的功能，必须优先在客户端实现。
- 采用 TypeScript + Obsidian Plugin API 作为主要技术栈。
- 可以使用适合 Obsidian 的轻量级前端框架构建交互界面。
- 不依赖 Linux 服务器、Docker、自建数据库、Python 后端、FastAPI 或独立 Web 服务。
- 不要求用户部署额外的服务端组件。
- 插件安装后，通过简单配置即可使用。

### 2. 云端 LLM

所有 AI 能力通过用户自行配置的云端 LLM API 实现。

要求：

- 支持 OpenAI-compatible API 接口。
- 支持自定义 Base URL、API Key、模型名称。
- 采用统一的 LLM Provider 抽象层，便于未来扩展其他厂商。
- 支持流式响应（在接口和客户端环境允许时）。
- 支持请求超时、重试、取消、并发控制。
- 记录 Token 消耗及预估费用（如模型价格信息可用）。
- 尽量减少不必要的 LLM 请求。
- 不允许将 API Key 写入日志、普通笔记或同步文件。
- 优先使用安全的设备本地凭据存储；若 Obsidian 当前平台缺少可靠的安全存储接口，需要明确说明限制，提供非持久化密钥输入方案，不能假设普通配置文件是安全的。
- 上传教材片段、答卷内容等到云端模型前，应向用户明确说明数据发送范围，并允许用户控制。

### 3. 本地数据优先

- Obsidian Vault 是学习资料和用户数据的主要持久化存储。
- 优先采用 Markdown + YAML Frontmatter 存储知识点、题目和学习笔记。
- 对结构化程度较高的试卷、答卷及评分明细，可以采用 JSON 存储。
- 数据格式必须开放、可导出、可迁移。
- 所有数据实体必须具备稳定唯一 ID。
- 支持题目版本、来源追踪和历史答卷快照。
- 不依赖外部关系型数据库或向量数据库。
- 本地全文检索优先考虑轻量级索引、关键词匹配及 BM25 等方法。
- 如需语义检索，可选用云端 Embedding API，但向量索引应在客户端缓存、可重建。
- 避免将大量索引数据纳入多端同步。

### 4. 多端兼容

目标平台：

- Windows Obsidian
- macOS Obsidian
- iPhone / iOS Obsidian

要求：

- 遵守 Obsidian 桌面端与移动端 API 的兼容性约束。
- 不直接依赖 Electron、Node.js 或其他仅桌面端可用的接口。
- 移动端页面适配触屏、小屏幕及资源限制。
- 较重的文档解析、索引和批量任务应分批执行，避免阻塞界面。
- 支持考试过程自动保存和意外退出恢复。
- 不依赖后台常驻进程。


## 三、核心功能模块

### 模块 A：资料与知识库管理

支持：

1. 导入或引用 Obsidian Markdown 笔记。
2. 导入教材 PDF、EPUB、TXT、Markdown 等资料。
3. 导入历年真题及标准答案。
4. 导入考试大纲和考点范围。
5. 手动维护知识点分类和重要程度。
6. AI 辅助提取章节、知识点、关键概念和关联关系。
7. 自动关联教材章节、考点、题目和笔记。
8. 支持资料更新后的索引增量更新。

PDF 解析优先考虑客户端可运行的方案，扫描 PDF 的 OCR 作为可选扩展，不得成为 MVP 的必要依赖。

每个知识点应至少支持：

- 唯一 ID
- 知识点名称
- 所属考试
- 所属科目和章节
- 考纲关联
- 重要程度
- 掌握程度
- 最近复习时间
- 下次复习时间
- 遗忘风险
- 相关题目
- 教材来源
- 关联 Obsidian 笔记

### 模块 B：题库管理

支持以下题型：

- 单选题
- 多选题
- 判断题
- 填空题
- 简答题
- 案例分析题
- 论文题

题目来源包括：

- 历年真题
- 用户手动录入
- AI 生成题
- 错题衍生题
- 指定知识点强化题

每道题必须记录：

- 唯一题目 ID
- 题型
- 题干
- 选项（如适用）
- 标准答案
- 答案解析
- 评分规则
- 难度
- 关联知识点
- 原始资料来源
- 真题年份（如适用）
- 生成方式
- 审核状态
- 题目版本

AI 生成的题目不能被标记为真实历年真题。

支持题目去重、题目编辑、答案校验和人工审核。

### 模块 C：智能定向组卷

支持以下组卷模式：

1. 考试大纲模拟组卷。
2. 指定教材章节专项组卷。
3. 历年真题模拟组卷。
4. 历史错题强化组卷。
5. 易忘知识点复习组卷。
6. 重要知识点专项组卷。
7. 综合自适应智能组卷。

用户可以设置：

- 考试或科目
- 考点范围
- 题目数量
- 题型及比例
- 难度等级
- 题目来源
- 考试时间
- 总分及评分规则
- 是否允许重复历史题目
- 是否使用 AI 生成新题

组卷逻辑必须采用 **规则引擎 + 本地题库检索 + 可选 LLM 生成**。

优先从已有题库选择符合条件的题目；现有题库不足时，再调用 LLM 补充。

AI 生成过程应使用 RAG 思路：

1. 识别目标考点。
2. 检索相关教材片段和标准资料。
3. 构造结构化出题提示词。
4. 调用云端 LLM。
5. 验证返回格式、知识范围及答案合理性。
6. 进行重复题检查。
7. 保存带有来源信息的题目。

不得让 LLM 在缺少可靠材料时随意编造事实或标准答案。

### 模块 D：考试与答题系统

在 Obsidian 内实现独立考试界面。

功能包括：

- 考试开始和结束
- 倒计时
- 上一题、下一题
- 题目导航
- 单选、多选交互
- 简答和案例题编辑器
- 论文题长文本编辑
- 标记疑问题目
- 实时答题进度
- 自动保存
- 未完成考试恢复
- 交卷确认
- 历史答卷查看

考试页面要同时适配电脑和手机。

### 模块 E：自动批阅与评分

客观题采用本地确定性规则评分，不调用 LLM。

主观题采用云端 LLM 辅助评分。

支持：

- 简答题要点匹配
- 案例题分项评分
- 论文题多维度评价
- 参考分数
- 漏答要点识别
- 错误概念识别
- 答案改进建议
- 参考答案展示
- 人工调整评分

主观题评分必须基于预定义评分规则和参考材料，输出结构化结果及评分依据。

AI 评分仅作为参考，不能宣称与官方阅卷完全一致。

批阅完成后生成考试报告，包含：

- 总分
- 各题得分
- 正确率
- 各知识点表现
- 错误原因分析
- 薄弱知识点
- 推荐复习内容
- 后续组卷建议

### 模块 F：错题与薄弱知识点管理

批阅完成后自动处理错题和知识点状态。

支持：

- 记录错题和错误次数
- 关联原题和原始答卷
- 分析错误原因
- 自动更新知识点掌握度
- AI 归纳常见错误
- 生成强化练习建议
- 支持手动标记已掌握
- 支持根据错题生成相似变式题

错误原因至少包括：

- 知识点未掌握
- 概念混淆
- 记忆不牢
- 审题错误
- 应用能力不足
- 其他

错题集应优先实现为基于原始题目和答卷记录的动态视图，避免复制同一题目的多个版本。

### 模块 G：自适应复习

根据历史答题表现建立知识点学习状态。

需要考虑：

- 历史正确率
- 错误次数
- 最近练习时间
- 答题耗时
- 知识点重要性
- 用户自评掌握度
- 间隔重复算法

初期可以采用 SM-2 等成熟的间隔重复算法，后续保留替换为更复杂算法的能力。

支持：

- 今日待复习知识点
- 即将遗忘知识点
- 高频错题
- 重要考点
- 薄弱知识点
- 自动生成每日复习试卷
- 复习完成后更新下一次复习时间

应区分由用户手动设定的“重要知识点”和系统预测的“薄弱或易忘知识点”。

### 模块 H：学习统计与知识看板

提供可视化学习分析，包括：

- 最近考试成绩趋势
- 各科目正确率
- 知识点掌握度
- 错题分布
- 题目完成量
- 每日复习情况
- 遗忘风险分布
- 重要知识点掌握情况
- 历史考试记录

统计数据尽量在客户端计算，不依赖云端 LLM。

## 四、技术设计要求

采用模块化、可测试、可维护的架构。

建议包含：

- Obsidian UI 层
- 业务应用层
- 题库与试卷领域模型
- 智能组卷引擎
- 本地评分引擎
- AI 评分服务
- LLM Provider 适配层
- 本地检索与索引模块
- 数据持久化模块
- 复习调度模块
- 学习统计模块
- 配置管理模块

要求：

1. UI 与核心业务逻辑解耦。
2. 业务逻辑不得直接依赖具体 UI 组件。
3. LLM 调用必须通过统一接口。
4. 数据操作必须通过统一 Repository 接口。
5. 支持严格 TypeScript 类型检查。
6. 对 LLM 输出进行 Schema 校验。
7. 核心业务逻辑编写单元测试。
8. 重要文件写入需要考虑失败恢复。
9. 防止重复创建试卷、答卷和评分记录。
10. 避免过度设计及无必要的第三方依赖。

## 五、UI / UX 设计

遵循 Obsidian 原生视觉风格，兼容明暗主题。

主要视图：

1. ExamFlow 首页
2. 资料与知识库管理
3. 题库管理
4. 智能组卷
5. 考试答题
6. 批阅报告
7. 错题中心
8. 复习计划
9. 学习统计
10. 插件设置

优先保证界面简洁、操作高效、移动端易用。

用户可以通过 Obsidian 命令面板执行常用功能。

## 八、最高优先级原则

整个项目始终遵守以下原则：

**本地优先、离线核心可用、云端 AI 增强、知识可追溯、数据归用户所有、无额外服务器依赖。**

不要因为 AI 功能而让普通题库管理、考试、客观题评分、错题记录或复习计划依赖网络。

不要因为需要知识检索，就默认引入独立向量数据库。

不要因为需要多端同步，就重新设计同步服务。

不要因为需要复杂业务逻辑，就引入不必要的后端。

请首先完成第一步的需求与架构设计，不要立即生成大量未经设计验证的代码。对 Obsidian API、iOS 兼容性、安全存储等不确定的能力，应核查官方文档并明确说明限制。
